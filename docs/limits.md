# What to know before you trust it

Voss is a character and a reference tool for health information and education. It can suggest possible explanations for symptoms, with sources, but it does not make diagnoses, treat or prescribe, and it is not a substitute for a doctor, pharmacist or emergency service. It can be wrong. In an emergency, call your local emergency number.

A figure a tool worked out carries the tag `[derived]`, and the line says what it was worked out from. A figure that was handed to the tool says who handed it over ("printed on the report, as given to the tool", "counted by the person"). This page is the longer answer, command by command.

- **Three databases are in: one explains words, one reads codes, one grades pairs of medicines.** `boot` and `sources` say what is installed and how old it is. What a medicine is and what its label says do not come from the toolkit yet: for those Voss looks things up with whatever the assistant can reach and cites them, or says he has no data.
- **`term` repeats a source; it does not examine anyone.** It prints the MedlinePlus summary of a health topic, or a short definition, in the source's own words, with the day the file was retrieved. The file is a copy, as old as that day: MedlinePlus itself is the current one, and a copy older than six months says so before it answers. The summaries were written for readers in the United States, so they name 911 and American services. A figure in a summary is general, and a lab value is still read against the range on your own report. When several entries could be meant it lists them and does not pick; when nothing matches it says "nothing on file", which is a gap in the file and not a fact about the word. Only the summaries are in it: not the pages MedlinePlus links to, not its encyclopedia, not its drug pages.
- **`code` reads a code back; it does not code anything.** It prints the title the World Health Organization gives an ICD-11 code, where the code sits in the classification and what is under it, character for character from the yearly release named in the output. The release file holds codes, titles and structure, and no descriptions: what a title means in practice is Voss's own explanation, said as his. It is ICD-11 only. A code from ICD-10, which much paperwork still uses, is not in it, and there is no table between the two, because WHO's licence keeps such tables for a written agreement. `--find` looks for words in the titles and nothing else: a title that holds your words is not a diagnosis, and WHO's wording may not be yours. A code on a letter is the doctor's; the tool cannot tell whether it was the right one.
- **`triage` is a checklist, not a judgement.** It prints the four levels and the red flags, word for word from `references/clinical-rules.md`. The list of red flags is not complete, and it says so.
- **Emergency numbers are passed on, not vouched for.** `triage --country` prints what Wikidata lists for a country, with what each number is for where Wikidata says. Nobody checked them one by one, a country may be missing, and a number marked for one service may reach others too. Inside the European Union 112 is put first, because the European Commission says it reaches every emergency service there. If you know your number, use it; if you do not and it is urgent, do not wait for a tool.
- **`visit` is general advice.** Its lists were written for this skill. No database is behind them, and nothing in them is about your complaint.
- **`labs` knows no reference range.** It reads the value you give against the range you give, which should be the one printed on your own report, and says which side of it the value falls on. It does not know what the test measures, and it does not turn a result into a diagnosis. A value the lab printed as "<0.5" is treated as exactly that: where it cannot be placed against the range, the tool says so. If the lab's flag and the printed range disagree, it asks you to read the report again.
- **`interact` and `watch` pass on a grade; they do not judge a combination.** They read pairs of medicines and the grade DDInter 2.0 gives each pair (Major, Moderate, Minor, or none). That is all DDInter lets anyone download, so there is no account of why two medicines interact and none of what to do about it: that question goes to a pharmacist or a prescriber, with the grade. Three things make "not listed" worthless as reassurance, and the tools say so every time. The file is partial: a pair is in it only if one of its two medicines belongs to certain groups of the ATC classification, so two medicines for the heart, two for the nervous system or two against infections are not there at all. Where the files prove that both medicines are outside those groups, the pair is reported as "out of reach" and not as unlisted; where they cannot prove it, an unlisted pair may still be one the file could never have held. It knows nothing of doses, of food, drink or herbs it cannot name, or of the person's kidneys, liver, age or pregnancy. And DDInter itself warns that the absence of an interaction does not mean there is none. A grade is about two substances, not about you. Names are a weak point: a medicine is found under DDInter's name or under another name taken from Wikidata, matched by spelling and not checked one by one. The output says what each name was read as; if that is not your medicine, the answer is not about your medicine. A brand name it does not know is reported as unknown and is checked against nothing.
- **`schedule` repeats a schedule it was given.** It never sets one, never tidies one, and does not know whether a dose is right. Dose times are written into the calendar without a time zone, so 08:00 stays 08:00 where you are; a calendar application that insists on a zone will use its own. That means the reminders follow the phone's clock when you travel: right for most tablets, wrong for anything taken at a strict interval, so ask the pharmacist or the prescriber how to carry such a medicine across time zones. Anyone who can see the calendar can read the entries, and a phone may show them on its lock screen: `--discreet` leaves the names out. The file is never written into a git working tree or into the skill's own folder.
- **`refill` is arithmetic on that schedule.** It assumes every scheduled dose was taken, from the day the pack was opened and counting that whole day, because it cannot know otherwise. Missed doses, extra doses and a second pack are invisible to it. Where the sums do not fit (the pack should have run out already) it says so and stops. It uses this machine's clock unless you pass `--now`, and a remote machine's clock may be hours from yours. When it matters, count the pack.
- **The gate is a soft lock.** `ignition` judges a reply against the answers on file, forgiving case, accents, word order and small typos, and never prints one. It judges and does nothing more: the other commands do not check that it was passed, nothing counts failed attempts, and nothing stops an assistant from opening the file. So keeping a file shut until then, keeping to three questions, and not looking are Voss's rules to follow. That stops a file being read aloud to the wrong person in a conversation. It is not encryption: the file is plain JSON, and anyone who can open the package can read it. Once passed, a gate stays open for the conversation.
- **Nobody is turned away at the gate.** Someone who does not pass it gets the same care and the same knowledge, only without the personal file. There is no way round the gate for an emergency, and none is needed: the emergency answer is the number to call, and it never depended on the file.
- **`profile` reads back what you said, as you said it.** Ages are worked out from the date of birth on the day you ask; a year alone leaves a year's doubt, and the line says so. "Stale" notes (a profile nobody has changed for over a year, a pregnancy status over thirty days old, medicines told over a year ago, travel over three months ago) are reminders to ask again. Nothing is deleted for being old. `boot` shows the day the file was last changed, which also tells you whether the copy that is loaded is the one you saved last.
- **`intake` and `rebuild` store only what was read back.** The code `intake` prints stands for exactly the file that would result; a different change, a changed file or a different day gives a different code, and `rebuild` then refuses. That makes the read-back hard to skip. It cannot make anyone listen to it.
- **The check for numbers that are never stored is a net, not a promise.** It recognises payment card numbers, IBANs, US social security numbers written with their hyphens, and two national number formats by their check digits, plus a few tell-tale words. A number in another shape will get past it. Refusing those is still Voss's rule.
- **`forget` removes from the new file only.** The field, entry or profile is gone from the file it writes: no empty slot, no note that it was there. The package or file you used until then still holds it, and so do backups and anything already said in a conversation. Delete the old copies yourself.
- **`rebuild` writes a private file.** A rebuilt package has your personal file in it, and the household file if your copy has one. The tool refuses to write it into a git working tree or into the package it is running from. Where you keep it after that is up to you.
- **`check --reply` checks form.** Typography, the marker line, ear cues, a banner written wrongly, a few phrases that are never said, and length. It cannot tell whether a claim is sourced, whether the tone suits the person, or whether a reply is kind.
- **`selftest` checks the toolkit on this machine**: known answers for the date sums, the refill sums, the lab comparison, the calendar format and the gate; that the data files and pictures are present; that each database says where it came from and that its packed text can be read by this Python; and that the personal file, if there is one, reads and has nothing to fix. It says where a problem is and never quotes what is written there.
- **Voss himself is fiction.** The android, the fur and the cyan eyes are a character. The rules he follows are real.
